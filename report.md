# WEEK 1 INTERNSHIP TASK REPORT
## Transforming Wireframes into Static Web Pages

### 1. Objective

The aim of this task was to turn a basic webpage layout into a working static website using HTML and CSS. I wanted to understand how different sections of a webpage are organised and how styling can make a website look clean, attractive, and easy to use. I created a website with a navigation bar, welcome section, about section, information cards, contact section, and footer.

### 2. Tools and Technologies Used

- **HTML5:** Used to create the structure and content of the webpage.
- **CSS3:** Used to style the page, arrange elements, and make the layout responsive.
- **Visual Studio Code:** Used to write and manage the code.
- **Google Chrome:** Used to open and check the webpage.

### 3. Implementation Details

I started by creating the basic structure in `index.html`. I divided the page into different sections so visitors could understand the content easily. I used semantic HTML elements such as `header`, `nav`, `main`, `section`, `article`, and `footer` to organise the content.

I then created a separate `style.css` file and linked it to the HTML file. I used CSS to add colours, spacing, typography, borders, rounded corners, and shadows. Flexbox helped me align the navigation items, while CSS Grid helped me arrange the information cards in columns.

I also added navigation links that move visitors to different sections of the same page. Hover effects were included to make links and cards feel more interactive.

### 4. Responsive Design

I wanted the webpage to remain readable on desktop, tablet, and mobile screens. To achieve this, I used CSS media queries with breakpoints at 768px and 480px.

At widths of 768px or less, the card layout changes from three columns to two columns. At widths of 480px or less, the cards are displayed in a single column, the navigation can wrap onto another line, and the hero section becomes more compact.

These changes help the content fit smaller screens instead of keeping the same layout everywhere.

### 5. Challenges Faced and Solutions

One challenge was planning a layout that would remain organised when the screen size changed. A three-column card layout may look good on a large screen, but it can feel crowded on a mobile phone.

I addressed this in the CSS by changing the number of columns at different screen widths. I also allowed the navigation links to wrap on smaller screens so they would have enough space.

Another consideration was keeping the design consistent. I used a common colour palette, similar spacing, and matching card styles to give the page a more uniform appearance.

### 6. Testing and Evaluation

The webpage should be checked in Google Chrome at desktop, tablet, and mobile widths. During testing, I will check the navigation links, text readability, card alignment, spacing, and footer.

I will also verify that the layout changes correctly at the 768px and 480px breakpoints and that the page does not have unwanted horizontal scrolling. Screenshots of the actual desktop, tablet, and mobile views can be included as evidence of the implementation.

The final testing results should be recorded after checking the page in the browser.

### 7. Improvements Made

I improved the page structure by using semantic HTML elements and keeping the HTML and CSS in separate files. I organised the CSS using sections and reusable colour variables to make future changes easier.

I also included responsive layouts, hover effects, keyboard focus styles, and spacing adjustments. These improvements make the webpage easier to maintain and help provide a better user experience.

### 8. Learning Outcomes

Through this task, I gained practical experience in creating a webpage using HTML and CSS. I improved my understanding of semantic HTML, Flexbox, CSS Grid, media queries, and basic styling techniques.

I also learned that creating a webpage is not only about making it look good on a computer. It is important to check how the content behaves on different screen sizes and make adjustments when necessary.

### 9. Conclusion

Overall, this task helped me strengthen my frontend development basics. I learned how to organise webpage content, apply CSS styling, and create layouts that adapt to different screen sizes. It also helped me understand the importance of testing and documenting my work.

I will use the knowledge gained from this task to improve my future web development projects and continue learning more advanced frontend techniques.
